## 3. 資料架構（Phase 4 起的案例引擎）

| 模組 | 內容 | 可見性 |
| --- | --- | --- |
| SOP 教材 | 單元、核心教學、練習題 | 公開（教學示範，需教師審核） |
| 小遊戲題庫 | 遊戲 A–D 題目 | 公開（教學示範，需教師審核） |
| 案例基本資料 | 病人設定、場景、時間、任務 | 依授權 |
| SP 對話腳本 | 問題節點 → 回答、情緒、肢體 | **受限** |
| 問題與回答節點 | 主題分類、問句變體、對應評分要項 | **受限** |
| 條件式追問規則 | 前置條件（已問過 X）→ 解鎖追問；SP 主動提問觸發條件 | **受限** |
| 檢驗報告 | 項目、數值、參考區間、項目說明 | **受限** |
| 評分規準 | 項目、0/1/2 判準、對應問題節點、審核狀態 | **受限** |
| 個別化回饋規則 | 依「已問／部分／未問」產生的回饋句 | **受限** |

問診引擎只讀取「案例包（case package）」JSON；新增胸痛、腹痛、呼吸困難等案例時，只需新增一個案例包，不需改引擎。

每個問題節點記錄：
- `askedStatus`：已詢問且取得資訊／已詢問但不完整／尚未詢問／**教案未提供明確答案（待教案作者補充）**
- `unlockAfter`：條件式追問（例如問了週期之後才出現「每次持續幾天」）
- `rubricLinks`：對應評分要項與子要項（例如月經史拆成多個子要項分別判斷）

## 4. 公開／非公開資料分離

正式教案包含考官指引、SP 劇本與評分規準，**不得**放入公開 repo 或公開網站。

1. **公開版**：只內建標示清楚的「教學示範案例」。
2. **受限案例包**：由管理者保存（例如院內雲端硬碟），以「教案匯入」載入學員自己的瀏覽器；資料只存在該瀏覽器，不上傳、不進 repo。
3. **授權確認**：每個案例包含 `license.publicApproved`，未經管理者確認為 `true` 的案例永遠不會被建置進公開網站。
4. 評分規準與題目對應保留 `reviewStatus`（`draft` / `reviewed`）與審核者欄位；未審核內容在畫面上標示「待審核」。
5. 所有自動評量標示「模擬形成性評量」，不等同正式 OSCE 考官評分；整體表現欄位獨立，不與規準分數相加。

## 6. 測試方式（Phase 1–3）

1. 群島 → 點選病史詢問島 → 島上出現四棟建築標籤；點建築直接進入，或按「進入學習區」到總覽。
2. SOP 學院：六個單元皆可完成「教學 → 練習 → 回饋 → 重新練習／回總覽」。
3. 訓練場：遊戲 A–D 皆可完成並看到觀念說明；可重玩（題目會重新洗牌或抽題）。
4. 分析中心：完成的單元與遊戲會出現在紀錄中，並依分數建議重練單元。

## 7. 虛擬病人診間（Phase 4–7）

- 引擎：`clinic/engine.ts`（問題解鎖、SP 提問觸發、子要項涵蓋、宣告式評分、回饋句），與案例內容無關。
- 案例：`cases/case001-dizziness.ts`。SP 回答取自劇本；劇本未提供者為 `answer: null`，畫面顯示「待教案作者補充」。
- 評分：15 項規準 0／1／2 判準逐字取自考官指引；以 `count`／`tiers` 規則計算；整體表現 1–5 分獨立、由教師評估。
- 規準審核：`#/history/clinic/case-001/rubric`，可修改判準文字、標記審核、匯出 JSON；計分規則以案例檔為準。
- 新增案例：複製案例檔格式並加入 `CASES` 清單即可。
